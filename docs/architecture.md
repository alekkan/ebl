# Архитектура

## Компоненты

| Компонент | Где | Что делает |
|---|---|---|
| Сайт | Yandex Object Storage, бакет `ebl.su` (https — Certificate Manager, DNS — Cloud DNS); резерв — GitHub Pages, ветка `gh-pages`. Оба собираются из `prototype/` | карта (с подсказкой «куда сходить за очками» и «📍 Рядом»), тепловая карта, таблица, лента, правила, форма похода, вход |
| API-шлюз | Yandex API Gateway `ebl-api` (`infra/api-gateway.yaml`), каталог `ebl` | браузер ходит к Supabase только через него: сам Supabase за Cloudflare, а его в России режут провайдеры. Проксирует REST, Auth, Storage и функции как есть |
| База | Supabase Postgres, проект `yeerkfdgmhcmvdqzaoio`, eu-central-1 | журнал походов, бани, участники, входящий остаток, итоговая таблица |
| `tg-login` | edge-функция | вход через Telegram: проверка подписи → пользователь Supabase Auth → одноразовый `token_hash` |
| `tg-bot` | edge-функция, вебхук Telegram | походы из общего чата, модерация Комиссией, отметка «долгая», геоточки, клички, заявки «это я» |
| `recompute` | edge-функция | пересчёт таблицы по регламенту (`_shared/scoring.js`) → `standings`, `visit_points` |
| `sync-avatars` | edge-функция | раз в неделю сверяет фото профилей через Telegram Bot API |
| `week-results` | edge-функция | итоги недели в чат лиги: картинка с пьедесталом (SVG → PNG через resvg-wasm, шрифты вложены в `_shared/fonts.ts`) и подпись — один раз, когда по закрытой неделе всё решено |
| `bath-location` | edge-функция | уточнение точки бани с сайта: ссылка на карту, адрес или координаты (участник — только примерные точки, Комиссия — любые) |
| Хранилище | Supabase Storage | `proofs` — фото с отметками времени (закрытый; не используется с 26.09.2026 — долгий на доверии), `avatars` — фото профилей (публичный) |

Сайт — чистый HTML/CSS/JS без сборки. Библиотеки лежат в `prototype/vendor/` (с проверкой целостности SRI): Leaflet 1.9.4,
Leaflet.markercluster 1.5.3, Leaflet.heat 0.2.0, supabase-js 2.117.2. С CDN их не берём — cdnjs и jsDelivr за Cloudflare. Шрифты — Unbounded (заголовки) и Golos Text (текст) с Google Fonts. Подложка карты — тайлы OpenStreetMap
с CSS-фильтром (CARTO требует ключ, у Esri нет русских подписей).

`prototype/db.js` — слой данных. Если в `config.js` заданы адрес и ключ Supabase — боевой режим; если пусто — режим витрины:
данные из `prototype/data/*.json`, походы и отзывы в `localStorage`. Остальной код (`app.js`) от режима не зависит.

## Модель данных

| Таблица | Что хранит | Кто видит |
|---|---|---|
| `players` | участник: `nick`, `is_commission`, `photo_url` | все |
| `player_accounts` | Telegram-аккаунт: `tg_id`, `tg_username`, `auth_user`, `claimed_nick` (заявка «это я»), `tg_photo` | свой аккаунт и Комиссия |
| `baths` | баня: название, тип (`public` общественная / `spa` хуитнес / `private` частная), страна, регион, `lat/lng`, `precision` (`exact`/`city`/`region`/`country`), `status` (`ok`/`pending`/`rejected`) | все (кроме отклонённых) |
| `visits` | поход: баня, `entered_at` (заход; у бота — время поста: баню отмечают сразу после входа), `posted_at` (отметка — по ней неделя), длительность, `status` (`pending`/`ok`/`rejected`), кто создал и кто модерировал, `tg_link` (пост в группе) | участники лиги |
| `visit_players` | кто был в походе (`has_proof`, `photos` остались от проверки фото — не используются, править строки участникам нельзя) | участники лиги |
| `reviews` | отзыв: оценка 1–5 «веников», текст; у участника на баню может быть несколько (сходил ещё раз — написал ещё), в средней — последняя оценка каждого | все |
| `legacy_visits` | входящий остаток: походы по баням, годам и никам из таблицы (2023–2025 и 2026 до перехода) | все |
| `legacy_standings` | входящий остаток: общий и недельный зачёт 2026 до `cutover_week` | все |
| `standings` | итоговая таблица — пишет только `recompute` | все |
| `visit_points` | очки по каждому походу и участнику (разбивка по бонусам) — пишет `recompute` | участники лиги |
| `settings` | `season`, `cutover_week`, `functions_url`, `league_chat` | все |
| `player_aliases` | клички участников («Мамонтов» → Ден) для разбора компании ботом | участники лиги |
| `bot_sessions`, `bot_posts`, `bot_notifications`, `claim_notices` | черновики и отложенные посты бота, связь похода с постом, карточкой и вопросами бота, сообщения Комиссии о походах и заявках «это я» | только функции |
| `bot_log` | тип адресованных боту сообщений и ошибки обработки (без текста) | только функции |

Представление `bath_counts` — походы по баням, годам и никам (остаток + засчитанный журнал), без дат и компаний.
Оно работает с правами владельца: журнал закрыт, а эти агрегаты (как в старой таблице) открыты для карты и тепловой карты.

Триггер `player_accounts_photo` переносит фото из аккаунта участнику — в том числе в момент, когда Комиссия подтверждает заявку.
Триггер `player_accounts_notify` зовёт бота: новая заявка «это я» → уведомление Комиссии (`tg-bot?claim`), подтверждение → `tg-bot?linked`.

## Права доступа (RLS)

Все таблицы под RLS, права выданы явно (в проекте выключена автоматическая выдача прав на новые таблицы).
Помощники: `me()` — id участника текущего пользователя, `is_commission()`.

- Отметить поход можно только от своего имени (`created_by = me()`) и только со статусом `pending`.
  Сайт делает это функцией `submit_visit(p_bath_id, p_new_bath, p_bath_type, p_entered_at, p_duration_min, p_companions)` —
  новая баня, тип со слов автора, поход и компания одной транзакцией; проверяет длительность (от часа), время захода
  (не в будущем, в сезоне `settings.season`) и отбрасывает повторы и неизвестные id в компании. Возвращает `{visit_id, bath_id}`.
- Служебные поля похода от участника ставит база (триггер `visits_site_defaults`, только для роли `authenticated`):
  `posted_at = now()`, `source = 'site'`, без `tg_link`, `long_asked_at`, `moderated_at`. Бот (service role) пишет их сам.
- Засчитать, отклонить и править любую заявку (баня, время, длительность, компания) — только Комиссия.
- Компанию добавляет автор похода, пока тот на модерации; Комиссия правит её удалением и вставкой строк.
  Править строки `visit_players` (update) не может никто из участников — иначе можно было переписать себя в чужой поход.
  Долгий — на доверии (п. 15): подтверждать не нужно.
- Новую баню участник может предложить (`status = pending`), принимает Комиссия. Пустой тип бани участник может заполнить
  (`suggest_bath_type`, кроме отклонённых бань).
- Заявка «это я» — функция `claim_nick(nick)`; привязывает аккаунт Комиссия.
- Итоговую таблицу пишет только `recompute` через `recompute_apply` (service role): `standings` и `visit_points` —
  одной транзакцией под advisory-замком, чтобы параллельные пересчёты не сталкивались.

Edge-функции работают с service role и сами проверяют, кто пришёл: `tg-login` — подпись Telegram, `tg-bot` — секрет вебхука
и привязку `tg_id`, `bath-location` — JWT пользователя и членство в лиге.

## Секреты (Supabase → Edge Functions → Secrets)

| Имя | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен @eblsu_bot — подпись входа, Bot API. Вписывает владелец сам, в чат не присылать |
| `TELEGRAM_WEBHOOK_SECRET` | секрет вебхука бота (заголовок `X-Telegram-Bot-Api-Secret-Token`) |
| `SITE_URL` | адрес сайта для ссылок в сообщениях бота (`https://ebl.su/`) |
| `ALLOWED_ORIGINS` | (необязательно) CORS для `tg-login`/`bath-location`; по умолчанию ebl.su, alekkan.github.io, localhost |

Публичный ключ Supabase (publishable) лежит в `prototype/config.js` — так и задумано: доступ ограничивают политики.
Числовой id бота в `config.js` тоже публичный, это не токен.

## Расписания (pg_cron)

| Задание | Когда | Что |
|---|---|---|
| `ebl-daily-recompute` | 00:05 МСК ежедневно | `recompute`: закрытая в воскресенье неделя получает очки за места |
| `ebl-weekly-avatars` | понедельник 04:00 МСК | `sync-avatars` |
| `ebl-week-results` | каждые 5 минут | `week-results`: с 23:00 воскресенья до конца среды постит итоги закрытой недели, когда нет походов на проверке, новых бань на согласовании; черновики в боте не ждём (`week_posts` — какие недели уже объявлены) |

Триггеры `visits_announce_verdict` (смена статуса похода → `tg-bot?verdict=<id>`), `visits_notify_site` (новый поход с сайта →
`tg-bot?new=<id>`), `visits_changed` / `visit_players_changed` (поправили баню, время, длительность или компанию →
`tg-bot?refresh=<id>`) и `player_accounts_notify` (заявка «это я» и её подтверждение) берут адрес функций из `settings.functions_url`, чат лиги для решений по походам с сайта — `settings.league_chat`.

Расписания лежат в миграциях с зашитым адресом боевого проекта. На локальном стенде их стоит снять, а `functions_url` переключить на локальный:
`select cron.unschedule(jobname) from cron.job;` — иначе локальная база будет дёргать боевые функции.

## Вход через Telegram

1. Сайт открывает `oauth.telegram.org/auth?bot_id=…&origin=…&return_to=…` полноценной страницей (без попапов — они терялись).
2. Telegram возвращает на сайт с `#tgAuthResult=<base64 JSON>`.
3. `db.js` отправляет данные в `tg-login`: проверка HMAC-SHA256 с ключом `sha256(bot_token)` (сравнение за постоянное время)
   и свежести (час).
4. Функция находит аккаунт по `tg_id` или заранее вписанному `tg_username` (точное совпадение без учёта регистра: `_` и `%`
   экранируются, иначе `v_tek1987` входил в чужой `vitek1987`), заводит пользователя Supabase Auth
   (служебный адрес `tg<id>@users.ebl.app`, письма не уходят) и отдаёт `token_hash` одноразовой ссылки.
5. Сайт меняет его на сессию: `supabase.auth.verifyOtp({ type: "magiclink", token_hash })`.

Домен входа задаётся у бота в @BotFather (`/setdomain`) и должен совпадать с адресом сайта.
