## Как работать с владельцем

- **Отвечать по-русски** — весь чат, пояснения и итоги, даже если сводка контекста на английском (27.09 после сжатия
  контекста агент перешёл на английский — владелец спросил, почему). Коммиты, PR, доки — тоже по-русски.
- **Интерфейс — спокойный:** простой текст, списки, один акцент; без плашек, номеров «01», рамок, цветных таблеток,
  свечений. Длинные заголовки — обычным жирным. Выделение только с функцией. Меньше текста, без дублей.
- **«Сделай человечнее» про тексты** — менять только формулировки; цифры, логику и структуру не трогать.
- **Выкладка — с согласия** («да, выкладывай»). Мержит и выкладывает агент сам (16.10: «так давай сам все выкладывай»),
  просить владельца нажимать merge не надо. Если проверка прав не пускает `gh pr merge` — сослаться на его согласие.
- **Данные на бою** — только по явной просьбе; сначала показать `select`-ом, что изменится, применять после «да»/«ок».
  Удалять — только по явным id. Классификатор прав без явного «да» запись на бой не пропускает — это нормально, спроси.
- **Секреты** не просить в чат и не печатать. Если владелец сам прислал ключ (2ГИС: «не парься, он одноразовый») —
  записать в `~/.config/ebl/keys` и не повторять в ответах.
- **Предлагать ускорения самому:** владелец спросил «почему раньше не предложил» про долгие повторяющиеся шаги.
- **Перед долгим шагом** (check.sh ~4 мин, выкладка) — напомнить: крышку Мака не закрывать (19.10 Мак уснул, проверки
  стояли 64 минуты, владелец решил, что агент сломал тесты; проверка — `pmset -g log | grep Sleep`).
- **Не плодить вопросы:** есть разумный вариант — делай и скажи, что выбрал. Но решения владельца не переигрывать.
- Для длинных задач с агентами владелец разрешает тратить их «по максимуму» («пофиг на агентов»), но не лимиты
  чужих сервисов: капчи, 429 и антибот не обходим.

## Радар — поиск общественных бань (подробно — docs/radar.md)

- **Что это:** все общественные бани России для Комиссии; на карту лиги попадают только кнопкой Комиссии. Идея
  владельца 16.10. Прогон — локально агентами, не на сервере.
- **Состояние на 25.10:** в `radar_places` 3713 мест, общественных с индексом 70+ — около 1000; почти всё ждёт
  решений Комиссии. ~100 мест с пометкой «нужен звонок», ~490 из малых городов — «нужен поиск» (пустые карточки 2ГИС).
- **Определение Комиссии:** общественная = вход по билету за человека в общую парную, баня — главное; раздельность по
  полу — плюс, не обязательна. Термы, аквапарки, фитнес — «хуитнес» (`spa`). Тип — у отделения, не у здания.
  Метку 2ГИС «Общественная баня» ставят и саунам на 6 человек — без агентов не верить.
- **Источники:**
  - OSM — Overpass через зеркало maps.mail.ru; один большой запрос по всей России даёт 504 — делить запросы.
    Отдача низкая: 912 `public_bath` по РФ, из 150 разобранных общественных 14. Ещё 563 кандидата из OSM не разобраны —
    без решения владельца не гонять.
  - 2ГИС API — демо-ключи владельца (1000 запросов в месяц, `page_size` ≤ 10, `page` ≤ 5; ключ кончился —
    ответ 403 «key is blocked»). Запрос «общественная баня» 2ГИС понимает как свой фильтр. Условия 2ГИС ограничивают
    хранение — владелец решил: «ничего страшного, все храним». Ключ кончился — **сказать владельцу**, он даст новый.
    Первые два ключа исчерпаны, у третьего (`DGIS_KEY3`) осталось ~200 запросов, демо до ~23.11.
  - Яндекс API не подключали: п. 5.1.6 их условий запрещает хранить данные. Выдачу Яндекса через WebFetch вместо
    поиска не открываем — это обход лимита.
- **Только Россия:** «за пределами РФ не нужно», **«СНГ не трогай»** (окончательно, 24.10). У границы круг цепляет
  Казахстан — фильтр `NOT_RU` в `sweep.py`.
- **Правила для агентов** (в `scripts/radar/prompt.md`): один WebSearch на запись, только справочники (allowed_domains);
  страницы — только WebFetch; без curl с подменённым User-Agent и без внутренних ключей API со страниц (24.10 агенты
  так обходили лимит, когда кончился месячный бюджет организации); никаких личных данных в запросах (агент однажды
  подставил почту владельца в User-Agent геокодера); геокодер OSM — не чаще раза в секунду; черновики — в своей папке.
  Волны по 10 агентов × ~19 записей. Вкладка цен 2ГИС через WebFetch приходит пустой, zoon часто отвечает 429.
- **Скрытие дублей:** место ближе 150 м к точной бане лиги или с подсказкой на точную баню (без точки или ближе 1 км)
  на сайте не показывается (`radarNear`, `radarKnown`). «Наши» — только для примерных бань лиги. «Решено» — только
  если у бани есть точная точка («если точки нет, то в решено не двигай»).

## Грабли из практики (в дополнение к AGENTS.md)

- `supabase db query --linked -o json` урезает точность дробных чисел — сравнивать координаты с допуском (`abs(a-b) < 1e-7`),
  иначе апдейт «по точке» молча не находит строки.
- Сводки и выгрузки с боя больше 1000 строк — только постранично (`pagedAll`) или `rpc` одним json.
- Перед `gh pr merge` — `git status -sb` (не `ahead`), иначе последний коммит не попадёт в PR.
- `check.sh` — всегда с `set -o pipefail`, если режешь вывод.
- При сравнении бань по адресу «улица Ленина, 1» есть в каждом городе — по адресу только без точек у обоих
  (24.10 Саратов слился с Самарой).
- Подсказки «это наша баня» ошибались на общих словах — стоп-слова (банька, отель…), город — целым словом,
  «рядом» — только для точных точек.
- Агенты в фоне отчитываются по одному; итог волны считать скриптом по `out/*.json`, не по их словам.
