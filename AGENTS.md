# Инструкция для ИИ-агентов

Проект — портал Евразийской банной лиги (ЕБЛ): сайт https://ebl.su, Telegram-бот @eblsu_bot, бэкенд на Supabase.
Прочитай [README.md](README.md) и нужный документ из `docs/` перед изменениями — там устройство, правила подсчёта и регламент работ.

## Язык и термины

- Интерфейс, тексты бота, комментарии в коде и коммиты — **по-русски**, коротко, на «ты», без канцелярита.
- Модератор лиги — **«Комиссия»**, не «секретарь» (внутренний мем лиги). В коде — `is_commission`, `is_commission()`.
- Тип бани `spa` в интерфейсе — **«Хуитнес»** / «Хуитнесы». `public` — «Общественная», `private` — «Частная».
- Поход в баню в разговорах лиги считают «банями» («у Шурика 110 бань»); кнопка — «Добавить баню».
- Недели — `W1…W52`, время — московское.

| Задача | Файлы |

## Правила продукта (решения лиги — не ломать)

- **Бот не захламляет чат.** На пост участника — одна карточка; дальнейшее (точка, «долгая», решение Комиссии) — правкой этой
  карточки и реакциями. Новые сообщения в группе — только когда без них никак (незнакомый участник, отказ по заявке).
- **Баню отмечают сразу после входа:** заход — время поста (кроме явного «с 18:00»). **Долгую отмечает сам участник** в течение
  8 часов после захода, можно сразу («@бот долгая будет» или в личку); сам бот не спрашивает. Длительность в интерфейсе — «⚡ Экспресс» /
  «🔥 Долгая», без минут.
- **Компания — явный выбор:** без попутчиков в посте бот спрашивает кнопками, а не пишет молча «один». Клички — `player_aliases`.
- **Движок очки за повтор в те же сутки не срезает** — подсвечивает Комиссии (бани кидают и за вчера).
- **Комиссия — роль**, без переключателей: кнопки решения и правка заявок видны ей сразу.
- **Из браузера — ничего через Cloudflare** (в России его режут): библиотеки — в `prototype/vendor/`, не с cdnjs/jsDelivr/unpkg;
  API — через шлюз `ebl-api` в Яндексе (`supabaseUrl` в `config.js`), напрямую — только запасным путём (`directUrl`), если шлюз
  не ответил (у части VPN он недоступен). Это проверяет `tests/test_site.py`.

## Правила изменений

- **Новые таблицы:** включай RLS и выдавай права явно (`grant … to anon/authenticated/service_role`) — в проекте выключена
  автоматическая выдача прав. Служебные таблицы бота — только `service_role`.
- **Журнал походов закрыт** для анонимов (видят только участники лиги). Агрегаты для карты — через представление `bath_counts`.
  Не открывай даты и компании наружу.
- **Бот получает все сообщения группы** (режим приватности выключен), но обязан отбрасывать неадресованные ему сразу и
  не хранить их. В `bot_log` — только тип сообщения, без текста.
- **Секреты** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, service role key) — только в Supabase Secrets. Не проси
  владельца прислать токен в чат, не пиши его в код и логи. Publishable-ключ и числовой id бота в `config.js` — публичные, так задумано.
- **Режим витрины** (пустой `config.js`) должен продолжать работать — это страховка и удобство для вёрстки.
- Сохраняй стиль кода: короткие функции, комментарии «зачем», а не «что», русские тексты в интерфейсе.

## Проверка

```bash
supabase start && supabase db reset
docker exec supabase_db_ebl psql -U postgres -c "select cron.unschedule(jobname) from cron.job"
docker exec supabase_db_ebl psql -U postgres -c "update settings set value = '\"http://supabase_kong_ebl:8000/functions/v1\"' where key = 'functions_url'"   # триггер вердикта — на локального бота
cp -n supabase/functions/.env.example supabase/functions/.env
supabase functions serve --env-file supabase/functions/.env     # в отдельном терминале
scripts/check.sh                                                # все проверки: бэкенд, бот и сайт в браузере
```

`scripts/check.sh` гоняет `tests/test_backend.py`, `tests/test_bot.py` и `tests/test_site.py`. Последний открывает сайт
в настоящем Chrome против локального стенда за гостя, участника, Комиссию, на телефоне и в режиме витрины: любая
ошибка в консоли, упавший сценарий (поход через форму, «Засчитать») или вылезшая за экран вёрстка — провал.
`scripts/deploy.sh` без зелёных проверок сайт не выкладывает. Сайт только глазами «как гость» не проверяй —
часть запросов выполняется лишь у вошедших (так уже ломали: сортировка по несуществующему столбцу visit_points.id).
Новое поведение сайта — новый сценарий в `tests/test_site.py`.
Если меняешь бота — пройди ручной сценарий из `docs/bot.md` в тестовой группе.

**Тесты не ходят в интернет.** Telegram Bot API, геокодер OSM и npm-CDN для функций — заглушка `tests/stub.py`
(её поднимают сами тесты; адреса — в `supabase/functions/.env`, см. `.env.example`), сайт в браузере получает пустые шрифты
Google, прозрачные тайлы и ответ геокодера из заглушки, а любой другой запрос наружу — ошибка теста. Без сети всё проходит,
кроме проверок с пометкой `[сеть]` (настоящий геокодер, wasm на jsDelivr): они пропускаются строкой «– пропущено [сеть]».
Новый внешний сервис в функции — адрес через `_shared/hosts.ts` и ответ в заглушке.

## Как работаем (нас несколько — люди и агенты)

Подробно, по шагам и с командами — **[docs/workflow.md](docs/workflow.md)**, прочитай его перед первой задачей. Главное:

- **В `main` напрямую не коммитим** (ветка защищена на GitHub). Задача → свежий `main` → своя ветка (`feat/`, `fix/`, `docs/`,
  `ops/`, `data/`) → pull request (`gh pr create`, описание по шаблону) → зелёный `scripts/check.sh` → `gh pr merge --squash`.
  `main` = то, что можно выкладывать.
- **Выкладываем только скриптами** и только из актуального `main` (скрипты сами проверят ветку, чистоту, совпадение
  с GitHub, прогонят все тесты и без зелёных ничего не выложат):
  - сайт — `scripts/deploy.sh` (в хранилище Яндекса `ebl.su` и резерв в `gh-pages`; в `main` ничего не пишет, нужен `yc`);
  - миграции и функции — `scripts/deploy-backend.sh [функция …]` (без аргументов — все функции, в конце пересчёт таблицы);
  - после изменений в `scoring.js` — `scripts/deploy-backend.sh recompute`;
  - и сайт, и бэкенд — сначала бэкенд, потом сайт.
- Руками `supabase functions deploy` / `supabase db push` не выкладываем — так в обход тестов уже уезжали изменения.
- Перед выкладкой — «выкладываю» в чат разработки: одновременные выкладки перезаписывают друг друга.
- **Агент выкладывает только с согласия своего человека**, данные на бою меняет только по явной просьбе и сначала
  показывает `select`-ом, что изменится; удаляет только по явным id. Тесты не ослабляет, чтобы стало зелёным.
- Второй человек обязательно смотрит PR, если он меняет правила очков, права доступа, удаляет/переименовывает в схеме
  или правит данные на бою.

## Грабли, на которые уже наступали

- **Кэш статики** — версии `?v=` в `index.html` ставит `deploy.sh`; без них новая страница грузила старый скрипт (GitHub Pages кэширует
  на 10 минут). В Яндексе `index.html` заливается с `no-cache` и последней — после скриптов, на которые ссылается.
- **`gh-pages` перезаписывается `--force`** — GitHub сам коммитит туда `CNAME`. Домен ebl.su на GitHub Pages оставлен нарочно:
  это горячий резерв, откат — вернуть A-записи GitHub в DNS-зоне.
- **Расписания pg_cron в миграциях** зашиты на боевой адрес — на локальном стенде их снимай.
- **Режим приватности Telegram** не доставляет боту отметки `@бота` в группе — поэтому выключен.
- **Кириллица и `\b`** в регулярках JavaScript не дружат — используй `(?![\p{L}\p{N}])` с флагом `u`.
- **PostgREST** отдаёт не больше 1000 строк — используй постраничную выборку (`all()` в `db.js` и `recompute`);
  пакетная вставка требует одинаковых ключей во всех объектах.
- **Координаты со страниц организаций** (Яндекс) ненадёжны — в них бывают чужие точки. Берём только из ссылки или адреса с проверкой расстояния.
- **Telegram отдаёт файлы как `application/octet-stream`** — тип картинки определяем по сигнатуре.
- **Сетка `body` без `minmax(0, 1fr)`** раздувалась под ширину таблицы — телефон уменьшал всю страницу, нижняя навигация уезжала.
  Широкое — только внутри своего `overflow-x: auto`.
- **Нижнее меню на телефоне** — высотой `--nav-h`, ровно столько же `main` оставляет снизу; шапка `.top` выше углов Leaflet
  (z-index 1000). Раньше правило `max-width: 900px` перебивало телефонные отступы меню, низ вкладок уходил под него, а подпись
  карты рисовалась поверх (28.09). Проверяет `nav_free` в `tests/test_site.py`.
- **На телефоне без прокрутки внутри прокрутки:** карта и список листаются одним экраном, в карточках участника — тоже.
- **Стартовый `fitBounds` — с `animate: false`:** анимация зума иногда не доходила до конца, и карта оставалась в исходной точке.
- **Всплывающее окно Telegram Login** терялось — вход сделан полноценной страницей (`oauth.telegram.org/auth` → `#tgAuthResult`).
- **`scripts/check.sh | tail`** прячет провал: без `set -o pipefail` код возврата — от `tail`.
- **Геокодер OSM (Nominatim) отвечает 429** после частых прогонов тестов — поэтому страну по точке функции спрашивают у заглушки,
  а настоящий геокодер сверяется отдельной проверкой `[сеть]`, которая без ответа пропускается с пометкой.
- **Тесты ходили в интернет** (Telegram, jsDelivr, Nominatim, шрифты и тайлы) и на медленной сети падали каждый раз в новом месте
  (28.09) — теперь всё внешнее в тестах подменено (см. «Проверка»). Старый `supabase/functions/.env` без `TELEGRAM_API_URL`
  тесты не примут: допиши строки из `.env.example` и перезапусти `supabase functions serve`.
- **Часы Docker могут отставать от Mac после сна** — тогда `tg-login` отклоняет «данные входа из будущего» (похоже, так падал
  вход 28.09); время для тестовых данных тесты берут у стенда (`now()` в `tests/local.py`).
- **Без VPN сайт висел на заставке** — API Supabase и библиотеки с cdnjs/jsDelivr за Cloudflare, провайдеры в России его режут
  (28.09). Лечится шлюзом в Яндексе и `vendor/`; проверки с узлов check-host этого не видят — там дата-центры, а режут мобильных.
- **ebl.su с Мака владельца открывается криво из-за VPN** — доступность проверять снаружи (check-host.net), DNS — через dns.google.
- **Локальный стенд копит хвосты тестов** (засчитали и удалили поход без пересчёта) — тесты, которые сравнивают таблицу,
  сначала сами зовут `recompute`.
