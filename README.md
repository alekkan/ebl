# ЕБЛ — портал Евразийской банной лиги

## Что есть сейчас (прототип)

`prototype/` — статический сайт на реальных данных из таблицы Комиссии (выгрузка на 25.09.2026).

- **Карта бань** — 1144 бани из справочника, фильтры по типу, стране, участнику и сезону. Карточка бани показывает, кто и сколько раз был в 2026 и в прошлых сезонах, есть отзывы с оценкой.
- **Таблица** — общий зачёт 2026, профиль участника: бани по неделям, география, типы бань, отсечка 16 мест на Кубок.
- **Поход в баню** — форма, в которой очки по регламенту-2026 считаются на лету: поход, общественная, уникальная, ультрауникальная, регион, страна, долгий, компания К/КК/ККК.
- **Лента** — походы со статусами «на модерации», «засчитан», «отклонён» и режим Комиссии.
- **Жар** — тепловая карта походов по годам (2023–2026) для всей лиги или одного участника, с прокруткой по годам.

История прошлых сезонов привязывается к справочнику бань по названию (`scripts/matcher.py`): находится 97–98% походов, остальные — бани с неоднозначными названиями.

Походы, отзывы и новые бани в прототипе хранятся только в браузере (localStorage).

Опубликован на GitHub Pages: https://alekkan.github.io/ebl/ (домен ebl.su — после делегирования) (закрыт от поисковиков через `noindex`). Выложить изменения: `scripts/deploy.sh`.

Запуск:

```bash
python3 -m http.server 8765 --directory prototype
```

Обновить данные из таблицы:

```bash
curl -sL -o scripts/ebl.xlsx "https://docs.google.com/spreadsheets/d/1lo91bPkR0T4j1Pk3Edp9YtQjrwHt5t8zWWSVq9nNLkY/export?format=xlsx"
python3 scripts/extract.py
python3 scripts/geocode.py   # долго: Nominatim разрешает 1 запрос/сек, результаты кэшируются в scripts/geocache.json
```

## Боевая версия: Supabase + GitHub Pages

- `supabase/migrations/` — схема: участники и Telegram-аккаунты, бани, журнал походов, отзывы, входящий остаток из таблицы, политики доступа.
- `supabase/functions/tg-login` — вход через Telegram Login Widget (проверка подписи токеном бота → сессия Supabase).
- `supabase/functions/recompute` — пересчёт таблицы по регламенту (`_shared/scoring.js`).
- `prototype/db.js` — слой данных сайта; `prototype/config.js` — адрес проекта и публичный ключ (пусто — режим витрины).

Кто что видит: карта, таблица, тепловая карта и отзывы — все; лента походов, компании и фото — только участники лиги после входа.
Отметить поход можно только от своего имени, засчитывает Комиссия.

Переход с таблицы: недели до `cutover_week` (по умолчанию W40) берутся из таблицы Комиссии как входящий остаток,
дальше всё считает портал. Перед запуском перевыгрузи таблицу после закрытия последней «табличной» недели.

Запуск в новом проекте:

```bash
supabase login
supabase secrets set TELEGRAM_BOT_TOKEN=<токен от BotFather> --project-ref <ref>
scripts/deploy-backend.sh <ref>
```

Потом впиши в `prototype/config.js` адрес `https://<ref>.supabase.co`, publishable key и username бота, выложи сайт `scripts/deploy.sh`.
Участника Комиссии назначает SQL: `update players set is_commission = true where nick = '<ник>';`.
Username участников можно вписать заранее — тогда при первом входе привязка произойдёт сама:
`insert into player_accounts (player_id, tg_username) select id, '<username>' from players where nick = '<ник>';`

Локальная проверка: `supabase start`, `supabase functions serve --env-file supabase/functions/.env`.

## Как устроена таблица сейчас

- `все бани` — матрица «баня × участник → число походов» за сезон, плюс страна и регион. Строки прошлых лет тоже здесь (нужны для ультрауникальных).
- `недельный зачет` — число бань у участника за каждую неделю.
- `Общий зачет` — очки за места (вписываются руками) и суммы категорий У, УУ, Дл, К, Общ, Рег (тоже ведутся руками в шапке «все бани»).
- Журнала отдельных походов (кто, когда, с кем, сколько по времени) нет — поэтому всё считается вручную.

## Боевая версия

**Идея:** единица данных — один поход. Всё остальное (недели, места, категории, таблица) считается из журнала автоматически.

### Стек

- **Supabase** — Postgres, авторизация, хранилище фото. Бесплатного тарифа хватит.
- **Фронт** — этот же сайт, переписанный на Next.js или Vite, хостинг на Vercel.
- **Вход через Telegram Login Widget** — участник ЕБЛ = участник группы ОУД.
- **Telegram-бот в группе:** `/баня Сандуны 3ч @Ден @Шурик` + фото → черновик похода со ссылкой на пост (подтверждение п. 5.3). Бот же присылает итоги недели в воскресенье в 23:00 МСК.

### Модель данных

| Таблица | Поля |
|---|---|
| `players` | id, ник, telegram_id, joined_at, left_at (п. 2: очки только в период членства) |
| `baths` | id, название, тип (public / spa / private), страна, регион, lat/lng, parent_id (разряды одной бани), merged_into (дубли) |
| `visits` | id, bath_id, date_msk, posted_at (для отсечки 22:59), duration_min, has_time_proof, tg_message_link, status, created_by |
| `visit_players` | visit_id, player_id, proof_photos — у каждого своё подтверждение долгого похода (п. 15) |
| `reviews` | bath_id, player_id, оценка, текст, фото |
| `seasons` | год, правила (JSON: очки за места, бонусы) — регламент менялся от сезона к сезону |

### Движок подсчёта (п. 5–18)

Чистая функция `score(season, visits) → { weeks, standings }`:

1. Отфильтровать походы: ≥ 60 мин, первый в эту баню за сутки, пост в тот же день.
2. Неделя — по `posted_at`, отсечка вс 22:59 МСК; W1 = 1–4 января.
3. Места за неделю по числу бань, 15/12/10/8/6/4/2/1, дележ поровну с округлением до 0,1; пустая неделя не разыгрывается.
4. Бонусы за поход: +1, общественная +1, компания +1/+2/+3 (3–5 / 6–8 / 9+ в одни сутки), уникальная +1, ультрауникальная +1, новый регион +1, новая страна +1, долгий +1.
5. Итог и тай-брейк по числу бань.

Правила сезона хранятся в конфиге, поэтому архив 2023–2025 можно пересчитать по своим регламентам.

### Перенос данных

- 2026: походы до запуска импортируем как «входящий остаток» — суммы по категориям из таблицы, а дальше ведём журнал.
- Справочник бань — из `все бани`. Нужна чистка дублей между сезонами: названия пишутся по-разному, а от этого зависят ультрауникальные.
